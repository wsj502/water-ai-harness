# 原型与实现对比评估报告

> 评估日期：2026-10-29
> 评估对象：P0 高保真原型（`prototype/`，5 页纯 HTML+CSS） vs 正式实现（`apps/web` React SPA 为主，兼及 `apps/cli`、`apps/desktop`）
> 评估基准：`docs/articles/01-界面设计.md` 定下的「协议锚点」与 P0 验收清单
> 评估方法：逐页元素比对 + CSS 字节级比对 + 内核事件契约核对（`packages/core` 的 LoopEvent）

---

## 一、总体结论

**还原度高、方向正确：原型的核心价值——「界面是协议的镜像」——已兑现。** 原型里承诺的 7 个协议锚点中 5 个完整落地，设计系统做到了像素级平移（CSS 逐字节相同）。实现不是「截图复刻」，而是把静态 mock 全部换成了真实数据流，并在多处超出原型（思考块真正可折叠、插件加载错误可见、工作区路径穿越防护）。

**主要缺口集中在「承诺了但还没接线」的交互面**：上下文计量条、模型切换菜单、composer 功能 chips、运行中任务的实时展示、设置页 6 个板块只实现了 3 个。这些不是缺陷，而是 P0「所见即承诺」原则下尚未兑付的期票，建议排入后续阶段或从原型中降级标注。

| 维度 | 评分 | 说明 |
|---|---|---|
| 设计系统还原 | ★★★★★ | CSS 字节级一致，主题机制完整复刻 |
| 协议锚点兑现 | ★★★★☆ | 7 项承诺落地 5 项，缺上下文计量与模型切换 |
| 页面覆盖 | ★★★★☆ | 5 页全部有对应实现，深度不一 |
| 数据真实性 | ★★★★★ | 全部接真实 API/SSE，无残留假数据（任务进度条除外） |
| 超出原型 | ★★★★☆ | 中断、错误态、安全防护等原型未覆盖的场景都有处理 |

## 二、设计系统：字节级平移

- `prototype/assets/water.css` 与 `apps/web/src/water.css` **逐字节相同**（`fc /b` 比对无差异，23297 字节）。P0 验收清单中「CSS 变量化，P3 React 阶段可整体平移」一条完全兑现。
- 主题初始化脚本（`<head>` 内联、防 FOUC、`localStorage['water-theme']` 三档）从原型原样搬入 `apps/web/index.html`；`SettingsView.tsx` 用 TS 重写了同语义的 `applyTheme`，行为一致。
- React 侧用到的全部 class（`.tool-card` `.approval` `.badge.*` `.task-row.open` `.ws-*` 等）在 CSS 中均存在，无「写了样式名但 CSS 没有」的断链。

**风险：CSS 双份拷贝。** 两份 water.css 目前一致，但物理上是两个文件，后续任何一端改样式都会静默漂移。建议改为单一事实源（如 `packages/ui-tokens/water.css`，原型与 web 都引用/构建时拷贝），或至少加 CI 一致性校验。

**死 CSS 提示**：`.model-menu`、`.proto-nav`、`.chip`、`.kbd`、`.rule-table`、`.switch`（开关组件）、`.env-note`、`.cursor`、`.sidebar-foot` 等约 10 组类在 React 代码中零引用。它们属于「原型有、实现未接线」的元素（见第四节），保留合理，但属于待兑付清单的可视化索引。

## 三、协议锚点兑现核对（核心指标）

文章 01 的核心论点：原型每个视觉元素对应内核必须发出的一个事件。逐项核对：

| # | 原型承诺 | 内核/实现状态 | 结论 |
|---|---|---|---|
| 1 | 工具卡三段式生命周期（pending→running→done/failed，或 denied） | `LoopEvent`: `tool_pending / tool_approved / tool_denied / tool_result(isError, durationMs)`；`blocks.ts` 状态机完整映射 5 态 badge | ✅ 完整兑现 |
| 2 | 审批三档 once / session / deny | `POST /api/sessions/:id/approve` 校验并透传三档；Web 审批卡三按钮真实接线 | ✅ 完整兑现 |
| 3 | 思考块折叠 + reasoning 分通道 | `thinking_delta` 独立事件 → 独立 `thinking` 块，`<details>` 真正可展开看内容（**比原型更强**：原型只有静态折叠态） | ✅ 超出原型 |
| 4 | composer 常驻上下文计量（12.4k/128k） | 内核 `usage` 事件存在、server 累计进任务记录、CLI 有 `[tokens: in=.. out=..]` 输出；**但 Web composer 只显示 `model · via protocol`，无 token 计量** | ❌ 数据已有，UI 未接线 |
| 5 | 插件权限徽章安装前可见 | manifest `permissions` → `/api/plugins` → 卡片徽章；内核加载时强制风险级提升 | ✅ 完整兑现 |
| 6 | Provider 双协议抽象 | core 有 anthropic/openai 双适配器；顶栏与设置页展示真实 `protocol/baseUrl`；智谱 usage 上报坑已修（见 PITFALLS.md） | ✅ 完整兑现 |
| 7 | 主题三档 | 见第二节，含防 FOUC 内联脚本 | ✅ 完整兑现 |

**兑现率 5/7，且缺口 4 是「管道已通、只差龙头」**——usage 数据从 provider 到 SSE 到客户端事件流全程可达，Web 端只差一个聚合显示组件。

## 六、差距清单（按建议优先级）

| 优先级 | 缺口 | 理由 | 预估成本 |
|---|---|---|---|
| P0 | 运行中任务不可见（server 结束后才入库） | 违背「任务=正在发生的 Loop」核心定位；审批悬挂时任务页毫无感知 | 中：Loop 开始时先写入 running 记录，finish 时更新 |
| P0 | 上下文计量条 | 数据管道已通（usage 事件全程可达），只差 UI 聚合；这是原型承诺的用户可感知出口 | 低 |
| P1 | Esc 中断 / 审批键盘快捷键 | 原型设置页明确承诺；中断对长任务是关键安全阀（CLI 有 Ctrl+C 等价物吗？需核） | 低 |
| P1 | 「在会话中引用」上下文注入 | 工作区页的唯一协议锚点未落地 | 中 |
| P2 | 模型切换菜单 | model-menu CSS 就绪；需要 server 支持会话级模型覆盖 | 中 |
| P2 | 设置页权限规则表 + 行为开关 | 内核 permissions 已消费规则，UI 只读化是权宜之计，建议至少把规则表做成只读可见 | 低-中 |
| P2 | composer chips（思考/联网/附件） | 涉及内核功能（深度思考开关等），无对应内核能力前建议**从原型降级标注**，守住「所见即承诺」 | — |
| P3 | diff/语法高亮渲染、消息时间戳、会话 token 数、工作区切换 | 体验增强，非协议承诺 | 中 |
| P3 | 任务进度条去假数据化 | 无真实进度来源则改为步骤计数（如「步骤 4」） | 低 |

## 七、其他发现

1. **文档小瑕疵**：文章 01 开头写「3 页高保真」，实际为 5 页（正文表格也是 5 行），建议修正。
2. **死代码良性**：`.proto-nav` 等未用 CSS 类保留在同一份文件中，可接受；但若采纳「CSS 单一事实源」建议，可顺手标注 `/* P0 预留，未接线 */`。
3. **Mock 兜底好**：`WATER_MOCK=1` 离线模式让原型-实现的联调不依赖真实凭据，这个设计在评估中没有发现破绽。
4. **SessionMeta 缺 token 字段**：侧栏想显示原型的「12.4k tok」需要 server 在会话级累计 usage（目前只在任务级累计）。

## 八、结论

这是一个**罕见地守住了「UI 先行」纪律**的项目：原型不是画完就扔的效果图，而是准确预言了内核事件协议（7 锚点兑现 5，且 2 个未兑现项的数据管道都已铺好）。实现侧没有引入任何与原型冲突的设计语言，反而在安全（路径防护、审批超时全拒）、可观测（插件加载错误、任务失败原因）和工程化（SSE 手解析、中断传播）上补齐了原型无法表达的部分。

剩余工作不是「返工」，而是**兑付期票**：把 CSS 里已经等着的 `.model-menu`、`.cursor`、`.chip`、`.rule-table` 接上真实数据源，或按「所见即承诺」原则从原型中降级。建议按第六节优先级表推进，其中「运行中任务可见」是唯一涉及服务端语义变更的项，值得先做。
